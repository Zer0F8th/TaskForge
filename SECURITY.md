# Security Policy

Security issues are taken seriously. If you believe you have discovered a security vulnerability in this project, please report it responsibly.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

Instead, contact the project maintainer privately through GitHub or another private contact method listed on the maintainer's GitHub profile.

Maintainer: **Zer0F8th**

When reporting a vulnerability, please include as much of the following information as possible:

* A description of the vulnerability
* The affected file(s), component(s), or functionality
* The affected version, branch, or commit
* Steps required to reproduce the issue
* Any special configuration required to reproduce it
* A proof-of-concept, if available
* The potential security impact
* Any suggested mitigation or fix, if known

Please avoid accessing, modifying, or destroying data that does not belong to you while testing or demonstrating a vulnerability.

## Response

I will make a reasonable effort to:

* Acknowledge valid security reports
* Investigate and reproduce reported vulnerabilities
* Develop and release fixes when appropriate
* Credit researchers who responsibly disclose vulnerabilities, unless anonymity is requested

Response and remediation times may vary depending on the severity and complexity of the issue.

## Supported Versions

Unless otherwise stated, security fixes are generally provided for the latest version of the project.

Older releases, branches, or commits may not receive security updates.

## Responsible Disclosure

Please allow reasonable time for a vulnerability to be investigated and fixed before publicly disclosing technical details.

Public disclosure should ideally occur after a fix has been released or after coordinating with the maintainer.

## Bug Bounties

This project does **not** currently operate a bug bounty program.

Security research and responsible vulnerability reports are appreciated, but no monetary compensation should be expected unless explicitly stated otherwise.

## Scope

Only vulnerabilities directly affecting this project's code or functionality are considered in scope.

Issues involving third-party dependencies should generally be reported to the maintainers of the affected dependency unless this project introduces or exposes the vulnerability through its implementation.
